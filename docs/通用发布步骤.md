# 通用发布步骤（任何项目都能用）

> 版本 0.11.5。以前只写「手机版逆向skill」，现在项目、仓库、版本、附件都从参数/配置读，不写死。

## 0. 一次性准备
1. **令牌**：GitHub → Settings → Developer settings → Tokens（classic）→ 勾 `repo` → 生成 → 复制。
2. 回 App，点输入框上方「**存令牌**」胶囊（读剪贴板，存到 `~/.config/dsh-go/github-token`，权限必须 600）。
   ⚠ 不要把令牌发进聊天、不要贴到任何对话里。

## 1. 项目里放 `.publish.json`（可选，只当默认值）
```json
{
  "repo": "你的用户名/仓库名",
  "display_name": "项目显示名",
  "assets": ["build/包名-v{version}.zip"],
  "notes_file": "CHANGELOG.md"
}
```
- **命令行参数优先**，配置文件只填没指定的项。
- `assets` 支持 `{version}` 占位；会逐个算 sha256，并自动上传一个 `SHA256SUMS`。
- 附件路径含空格请加引号（脚本按行读取，不会拆开）。

## 2. 发布前人工做两件事
1. **改版本号**（脚本绝不自动改）
2. **写 CHANGELOG**（Release 正文从这里取；没有则用 `--notes`）

## 3. 先给用户看，确认后再发
把「版本号 + 本版更新」发给用户 → 用户说“确认发布” → 才执行下一步。
没有 `--confirmed` 脚本直接拒绝（在任何网络调用之前）。

## 4. 执行发布
```bash
bash <插件目录>/bin/publish.sh \
  --dir <项目目录> --version 0.1.0 --confirmed
```
常用参数：
| 参数 | 作用 |
|---|---|
| `--repo owner/name` | 指定/覆盖仓库 |
| `--assets "a.zip b.zip"` | 覆盖附件（支持引号内空格） |
| `--notes "文字"` / `--notes-file f` | 更新内容 |
| `--create-repo` | 仓库不存在时创建（**默认私有**） |
| `--public` | 配合 --create-repo 建公开仓库（默认私有） |
| `--dry-run` | 只预检，**不提交、不推送、不上传** |
| `--resume` | Release 已存在但附件为空时续传 |
| `--allow-overwrite` | 远端有本地没有的提交时才允许覆盖（默认拒绝） |

脚本行为（安全边界）：
1. 令牌必须 600；令牌只走 stdin，不进命令行参数
2. 认证失败 / 仓库不存在 / **tag 已存在** / 远端有本地没有的提交 → 直接拒绝
3. 提交前扫描私钥、GitHub 令牌
4. tag 只创建，**绝不移动已有 tag**；分支只允许快进，非快进就报错
5. 推送成功后把本地分支/tag 对齐到远端提交
6. Release 附件上传后**核对数量与大小**，不一致就 fail
7. 失败可加 `--resume` 重跑（Release 已空时复用）
8. 状态写 `/tmp/gh-publish.<项目名>.status`（多项目不互相覆盖）

## 5. 校验（下载者）
发布 Release 里会自动带 `SHA256SUMS`：
```bash
sha256sum -c SHA256SUMS
```
（项目自带的 verify 脚本属于各项目，不在插件里。）

## 6. 常见问题
| 现象 | 原因 | 处理 |
|---|---|---|
| 拒绝发布：未加 --confirmed | 没给用户确认 | 先拿确认 |
| tag 已存在 | 版本号没改 | 改版本号再发（脚本不会移 tag） |
| 非快进 | 远端有新提交 | 先同步，或确认后 --allow-overwrite |
| 附件上传失败 | 网络 | 加 --resume 重跑 |
| 插件按钮没出现 | 没重启内核 | 设置→插件→重启内核 |

## 7. 插件 vs 技能包
- **插件**（本插件）= App 按钮/面板
- **技能包** = 含 `SKILL.md` 的包
- 发布技能包：把 zip 放进 `assets` 即可

## 8. 新增参数（借鉴成熟发布工具）
| 参数 | 作用 | 借鉴自 |
|---|---|---|
| `--draft` | 先存草稿，确认后再手动发布 | gh CLI / goreleaser（draft 默认） |
| `--prerelease` | 标成预发布 | gh release create --prerelease |
| `--generate-notes` | 用 GitHub 自动生成变更汇总（基于上一个 tag） | gh release create --generate-notes |
| `--overwrite-files` | Release 已存在时删掉旧附件重传 | goreleaser replace_existing_artifacts |
| `--json` | 结束输出机器可读 JSON | gh CLI --json |
| 附件 glob | `--assets "dist/*.zip"` 自动展开 | gh release create 文件模式 |
| `--resume` | 中途失败后续传 | goreleaser replace_existing_draft |
